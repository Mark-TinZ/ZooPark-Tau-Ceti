# Руководство по разработке (Contributing Guide)

## 🌿 Правила работы с Git (Git Flow)

Чтобы история коммитов оставалась чистой, а интеграция кода проходила без конфликтов, при работе на выделенной ветке придерживайтесь следующих правил:

1. **Синхронизация — превыше всего:** Перед началом работы над новой задачей **всегда** делайте `git pull` (или fetch + rebase) и подтягивайте последние изменения из ветки `main`.
2. **Изоляция задач:** Для каждой новой задачи (новой механики, UI, багфикса) создавайте отдельную ветку. 
   * Формат нейминга: `тип/название-задачи` (например, `feature/animal-ai`, `ui/settings-menu` или `fix/chunk-saving`).
3. **Атомарные коммиты:** Старайтесь коммитить изменения сразу по мере выполнения логического куска задачи. Не сваливайте десятки разных изменений в один огромный коммит.

## 📂 Структура проекта и Архитектура

Проект ZooPark использует **Godot 4** и **GDScript**. Архитектура проекта жестко разделена на логические блоки для отделения системного кода от конкретных игровых механик.

* **Слой ядра (`core/`):** В этой папке лежат глобальные менеджеры (Autoloads/Синглтоны), такие как `ChunkManager` для стриминга мира, `GameSaveSystem` для сохранений и `ObjectPool` для оптимизации памяти. **Правило:** Здесь находится системная логика, которая работает постоянно.
* **Слой игровых фич (`features/`):** Здесь находится вся игровая бизнес-логика, разбитая по подсистемам: `features/game/`, `features/buildings/`, `features/ui/` и `features/world/`. Например, логика поведения ИИ (`features/ai/`) изолирована от логики UI.
* **Слой ассетов (`assets/`):** Все 3D-модели, звуки, текстуры и темы.

## 🛠 Сохранение состояния и Мир (Chunk System)

Мы используем кастомную систему стриминга чанков (`features/world/`) и сохранения (`core/game_save_system.gd`). Если вы добавляете новые сохраняемые объекты:

1. **Обязательно** наследуйтесь или используйте компоненты, которые регистрируются в `ChunkManager`, чтобы при выгрузке чанка объект сохранялся.
2. Проверьте правильность сохранения данных (сериализации) в `ChunkData`.
3. Примените изменения в тестовой сцене и убедитесь, что при перезагрузке состояние восстанавливается.

## 🧩 Работа с менеджерами (Autoloads / Singletons)

В проекте реализован механизм доступа к глобальным системам через синглтоны (Autoloads), настроенные в `project.godot`. Это означает, что вам **не нужно** вручную прокидывать ссылки на ключевые менеджеры.

* **Правильный подход:**
  Просто обращайтесь к глобальному менеджеру по его имени. Например, для работы с чанками:
  ```gdscript
  func _ready():
      ChunkManager.chunk_loaded.connect(_on_chunk_loaded)
  ```

## 🌍 Локализация (i18n)

Проект использует встроенную систему локализации Godot. Запрещается использовать жестко закодированные (хардкод) строки для ответов пользователям или текстов в UI!

1. **Файлы переводов:** Все тексты должны добавляться в файлы локализации (например, `.csv` или `.po` в зависимости от настроек проекта).
2. **Использование в UI:** В `Label`, `Button` и других Control-узлах просто указывайте ключ перевода (например, `UI_MAIN_MENU_PLAY`) в поле `text`, и Godot автоматически его переведет.
3. **Использование в коде:** Если требуется перевести текст из GDScript (например, всплывающее уведомление), используйте функцию `tr()`:
   ```gdscript
   notification_label.text = tr("MSG_NOT_ENOUGH_MONEY")
   ```

## 🎯 Приоритеты и задачи

1. **Разминка:** Начните с создания или улучшения UI (в папке `features/ui/`), чтобы познакомиться с правилами построения интерфейсов (Anchors, Containers) и архитектурой Godot.
2. **Работа со статусами и миром:** Если вы добавляете новый функционал на карту (например, новые типы зданий), старайтесь изолировать логику в `features/buildings/` и использовать `ObjectPool`, чтобы не вызывать лаги из-за частого `instantiate()`.
3. **Оптимизация 3D:** Всегда настраивайте LOD (`lod_bias`), Visibility Range и Occlusion Culling для новых 3D-объектов, чтобы сохранять высокий FPS при стриминге мира.

---
*Если у вас возникли вопросы по архитектуре или вы столкнулись с трудностями в GDScript — не стесняйтесь обращаться к ревьюерам в Pull Request!*
