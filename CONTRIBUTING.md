# Руководство по разработке (Contributing Guide)

## 🌿 Правила работы с Git (Git Flow)

Чтобы история коммитов оставалась чистой, а интеграция кода проходила без конфликтов, при работе на выделенной ветке придерживайтесь следующих правил:

1. **Синхронизация — превыше всего:** Перед началом работы над новой задачей **всегда** делайте `git pull` (или fetch + rebase) и подтягивайте последние изменения из ветки `main`.
2. **Изоляция задач:** Для каждой новой задачи (новой механики, интерфейса, багфикса) создавайте отдельную ветку. 
   * Формат нейминга: `тип/название-задачи` (например, `feature/animal-ai`, `ui/settings-menu`, `fix/chunk-saving`).
3. **Атомарные коммиты:** Старайтесь коммитить изменения сразу по мере выполнения логического куска задачи. Не сваливайте десятки разных изменений в один огромный коммит. Дайте коммитам понятные описания.

## 📂 Структура проекта и Архитектура

Проект ZooPark использует **Godot 4**. Архитектура построена на четком разделении между системным кодом и игровыми фичами.

* **Core (`core/`):** В этой папке лежат глобальные менеджеры (Autoloads/Синглтоны), такие как `EconomyManager`, `ChunkManager`, `SceneManager`. Если вы пишете подсистему, которая должна работать постоянно на фоне и управлять состоянием игры — ее место здесь.
* **Features (`features/`):** Основной игровой код и сцены (камера, здания, мир, UI). 
  * *Пример:* Логика поведения посетителей должна располагаться в `features/game/` или `features/entities/`, но не в корне проекта.
* **Ассеты (`assets/`):** Все визуальные и аудио-ресурсы лежат здесь. Группируйте их по типу и назначению (например, `assets/models/buildings/`).

## 🎨 Дизайн и UI-компоненты

Мы придерживаемся единого стиля интерфейсов.

* **Использование тем:** При создании новых UI-элементов опирайтесь на ресурсы и настройки, предоставляемые `ThemeManager` (`core/theme_manager.gd`).
* **Адаптивность:** Базовое разрешение проекта настроено на `1920x1080`. Обязательно используйте систему `Anchors` и контейнеры (`VBoxContainer`, `HBoxContainer`), чтобы интерфейс правильно масштабировался.
* **Виртуальный курсор:** Обращайте внимание на поддержку управления с геймпада через `VirtualCursorUI`.

## 🎯 Приоритеты и задачи

1. **Разминка:** Начните с создания или улучшения статических UI-экранов, чтобы познакомиться с `SceneManager` и структурой проекта.
2. **Игровая логика:** Для связи различных компонентов (например, когда покупка здания влияет на деньги) **используйте сигналы**, а не прямые вызовы. Подписывайтесь на `EconomyManager.money_changed`, чтобы реактивно обновлять UI.
3. **Работа с миром:** Если вы вносите изменения в сохранение состояния объектов на карте, всегда делайте это через `ChunkManager`. Это необходимо для правильной работы стриминга и сохранения без фризов.

---
*Если у вас возникли вопросы по архитектуре или вы столкнулись с трудностями в GDScript — не стесняйтесь обсуждать это в Pull Request!*

## 🚀 Оптимизация 3D-сцен

Для поддержания высокого уровня FPS в проекте (особенно с учетом открытого мира), все новые 3D-модели и сцены должны быть настроены по следующим правилам:

1. **LOD (Level of Detail):**
   * Для всех узлов `MeshInstance3D` устанавливайте `lod_bias = 1.0` (или подбирайте значение визуально, если требуется). Не делайте его слишком низким (например, `0.5`), чтобы модели не теряли полигоны слишком быстро.
2. **Дальность прорисовки (Visibility Range):**
   * Для тяжелых мешей (здания, детали ландшафта) обязательно настраивайте `visibility_range_end` (например, 100-150) и `visibility_range_end_margin` (например, 10-15), чтобы движок переставал рендерить их на расстоянии.
3. **Запекание света (Lightmap GI):**
   * Основной `DirectionalLight3D` остается в режиме **Dynamic**, чтобы движущиеся объекты отбрасывали тени.
   * Статичные объекты (здания, ландшафт) должны быть включены в `gi_mode = 1` (Static).
   * Если ваш меш сделан из базовых примитивов Godot (BoxMesh, CylinderMesh), вы можете включить галочку `add_uv2 = true` в инспекторе. **Если вы импортируете внешнюю 3D-модель (GLTF/FBX)**, не трогайте настройки сцены! Развертку UV2 нужно сгенерировать вручную через окно **Import -> Meshes -> Light Baking -> Gen UV2**.
4. **Отсечение невидимого (Occlusion Culling):**
   * Для статичных зданий-префабов добавляйте узел `OccluderInstance3D` с простым `BoxOccluder3D`.
   * Для объектов, геометрия которых генерируется процедурно в рантайме (как `chunk.tscn`), генерация `ArrayOccluder3D` должна происходить через код после создания меша.
